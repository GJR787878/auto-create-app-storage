> Автоматически создаёт отсутствующие каталоги `/storage/emulated/0/Android/data/<пакет>/{files,cache}` и `Android/obb`, исправляя ложную ошибку «Место в хранилище заканчивается» на кастомных прошивках.

---

## Предыстория

На некоторых кастомных прошивках (таких как crDroid, LineageOS и др.) система не создаёт автоматически приватные каталоги в `/storage/emulated/0/Android/data/` для установленных приложений. Когда приложение вызывает API проверки хранилища (например, `isOverStorageFreeSpace`), оно не может получить информацию о файловой системе, поскольку целевой каталог не существует — **даже при большом объёме свободного места приложение ложно сообщает «Недостаточно места»**, из-за чего нельзя прикрепить изображение, отправить файл или скачать вложение.

**Типично затрагиваемые приложения:**
- Doubao `com.larus.nova`
- Dola `com.larus.wolf`
- TikTok / Douyin `com.ss.android.ugc.trill`
- Telegram `org.telegram.messenger`
- Любые сторонние приложения, использующие приватный каталог Android/data

**Корневая причина:** каталог `/storage/emulated/0/Android/data/` почти пуст; подкаталоги `files/` и `cache/` приложения не были созданы системой.

---

## Возможности

- **Полное сканирование при загрузке**: автоматически сканирует все сторонние приложения после загрузки и создаёт отсутствующие каталоги
- **Мониторинг установки в реальном времени**: использует `inotifywait` для отслеживания базы пакетов; каталоги для новых приложений создаются за секунды
- **Умный запасной вариант**: автоматически переключается на опрос каждые 20 секунд, если `inotifywait` недоступен — дополнительные зависимости не требуются
- **Исправление владельца**: автоматически выполняет `chown` на UID приложения, обеспечивая доступ на чтение/запись
- **Исправление SELinux**: автоматически запускает `restorecon` для восстановления правильного контекста безопасности — каталоги существуют И доступны
- **Без конфликтов**: чистый Shell-скрипт, без внедрения Zygisk — полностью совместим с LSPosed, Sui, hosts и другими модулями

## Установка

### Способ 1: Прошивка через Magisk (рекомендуется)

1. Скачайте актуальный zip модуля:
   👉 [Скачать из Releases](https://github.com/GJR787878/auto-create-app-storage/releases/latest)
2. Откройте Magisk → Модули → Установить из хранилища
3. Выберите скачанный `auto-create-app-storage.zip`
4. Дождитесь завершения установки и перезагрузите устройство

### Способ 2: Сборка вручную

```bash
git clone https://github.com/GJR787878/auto-create-app-storage.git
cd auto-create-app-storage
zip -r auto-create-app-storage.zip module.prop service.d/
```

Перенесите полученный zip на телефон и прошейте способом 1.

## Проверка установки

После перезагрузки выполните в терминале (требуется Root):

```bash
# 1. Убедитесь, что модуль включён
ls /data/adb/modules/auto_create_app_storage/

# 2. Убедитесь, что фоновый наблюдатель запущен
ps -A | grep inotifywait

# 3. Проверьте, что каталог приложения создан (пример с Doubao)
ls -la /storage/emulated/0/Android/data/com.larus.nova/
```

В выводе должны присутствовать подкаталоги `files` и `cache`, владельцем которых является UID приложения.

### Функциональный тест

1. Удалите стороннее приложение (например, Doubao)
2. Переустановите его
3. Подождите 5–10 секунд
4. Выполните `ls /storage/emulated/0/Android/data/com.larus.nova/`
5. Каталоги появились автоматически → модуль работает

## Принцип работы

```
Загрузка
  │
  ├─ Magisk вызывает скрипт service.d
  │
  ├─ sleep 35 (ожидание системы, хранилища и сервисов Media)
  │
  ├─ Полное сканирование: pm list packages -3 → создание каталогов
  │     ├─ mkdir -p Android/data/<pkg>/{files,cache}
  │     ├─ mkdir -p Android/obb/<pkg>
  │     ├─ chown <uid>:<uid> (исправление владельца)
  │     └─ restorecon -R (исправление контекста SELinux)
  │
  └─ Постоянное отслеживание /data/system/packages.xml
        ├─ inotifywait доступен → события modify/attrib в реальном времени
        └─ inotifywait отсутствует → проверка mtime каждые 20 секунд
              └─ изменение обнаружено → sleep 2 → повторное сканирование
```

### Зачем нужен restorecon?

Каталоги, созданные только через `mkdir`, могут иметь неверный контекст SELinux (например, не помечены как `app_data_file`), поэтому приложение по-прежнему не может читать/записывать, хотя каталог существует. `restorecon` применяет правильную метку `app_data_file` из file_contexts — это критический шаг, который реально решает проблему.

## Частые вопросы

### В: После установки всё равно появляется «Недостаточно места»?

1. Убедитесь, что модуль включён в Magisk и вы перезагрузили устройство
2. Проверьте, создались ли каталоги: `ls /storage/emulated/0/Android/data/<пакет>/`
3. Если нет, запустите скрипт вручную: `sh /data/adb/modules/auto_create_app_storage/service.d/auto_storage_fix.sh`
4. Проверьте режим SELinux: `getenforce`; если Enforcing и доступ всё равно закрыт, проверьте контекст через `ls -Z`

### В: Каталоги системных приложений создаются?

Нет. Скрипт обрабатывает только сторонние приложения (`pm list packages -3`). Системные приложения управляются самой системой.

### В: Что происходит с каталогами при удалении приложения?

Система автоматически удаляет `/storage/emulated/0/Android/data/<pkg>`. После переустановки модуль обнаруживает изменение базы пакетов и автоматически воссоздаёт каталоги.

### В: Влияет ли это на /data/data/<pkg>?

Нет. Модуль работает только с внешним хранилищем `/storage/emulated/0/Android/data/` и не затрагивает внутренние каталоги данных.

### В: Конфликтует ли с модулями изоляции хранилища?

Если вы используете модули Storage Isolation, они могут перехватывать доступ приложений к Android/data. Этот модуль только создаёт каталоги и не изменяет политику доступа приложений к хранилищу.

### В: Как посмотреть журналы работы?

```bash
logcat | grep -i "auto_storage\|inotifywait"
```

## Удаление

1. Magisk → Модули → найдите AutoCreateAppStorageDir → Удалить
2. Перезагрузите устройство
3. Созданные каталоги приложений не удаляются (управляются системой или самим приложением)
